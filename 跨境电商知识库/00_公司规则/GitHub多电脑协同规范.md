# GitHub 多电脑协同规范

## 正式仓库

- 正式本地仓库：员工自行选择的 `Amazon-AI-OS` 克隆目录
- 正式远端仓库：`https://github.com/jinyanjie321-commits/Amazon-AI-OS`
- 仓库类型：公司私有仓库
- 协同工具：第一版统一使用 GitHub Desktop；命令行 Git 作为后续增强项
- 当前电脑的外层历史工作区不作为团队同步仓库

## 员工电脑使用规则

- 每台员工电脑只克隆并打开正式仓库 `Amazon-AI-OS`。
- Obsidian Vault 打开正式仓库内的 `跨境电商知识库`。
- Codex 工作区选择正式仓库根目录。
- 每天开始工作前先在 GitHub Desktop 同步最新版本，提交前先拉取最新版本。
- 修改 SOP、模板、Agent 提示词、角色权限或机器配置后，必须提交到 GitHub。

## 不进入 GitHub 的内容

- 密钥、Token、账号授权状态、Cookie、本机临时配置。
- `node_modules`、`.codex/downloads`、`.codex/tools`、缓存、运行包和临时输出。
- 原始大附件、培训包、导出压缩包和未整理资料源。
- 黑帽隔离资料及路径或文件名命中隔离关键词的资料。

## 分支建议

- `main`：稳定规则、模板、配置和已批准知识。
- `ops/sop-update`：运营主管维护 SOP。
- `ads/report-template`：广告报表模板和诊断规则调整。
- `ai/agent-config`：Agent 注册表、路由和提示词调整。

## 老板审批项

- 创建、迁移或删除公司私有仓库。
- 邀请或移除成员。
- 设置团队权限和目录访问策略。
- 决定员工是否可以克隆完整 Vault。
- 切换正式远端仓库，例如从 `jinyanjie321-commits/Amazon-AI-OS` 迁移到其他仓库。

## 完整合规 Vault 授权例外

- 老板已批准所有员工电脑接收完整合规 Vault。
- 隔离目录、禁用关键词资料、原始资料库、密钥、令牌、本机授权状态、缓存和运行输出不属于该授权范围。
- 完整合规 Vault 通过 AES-256 加密离线包交付，密码必须通过独立渠道传递。
- 角色矩阵中的智能体调用权限、修改权限和操作审批要求继续生效。

## 当前已知限制

- 本机 GitHub Desktop 已完成发布和同步；命令行 Git 仍缺少远端凭据。
- GitHub 仓库是否为 Private、团队分组权限是否正确，需要老板在 GitHub 页面最终确认。
- 父目录存在历史本地仓库痕迹，团队协同时以子目录正式仓库为准。
