# Amazon-AI-OS 闭环测试与验收

## 验收目标

闭环合格必须同时满足：

- 指令进入任务主账本并获得唯一任务编号。
- 完成安全检查、数据完整度检查和风险分级。
- 知识引用和 MCP 调用均可追溯，缺失数据明确标注。
- 专项智能体按统一输出契约交付。
- 中高风险动作未经审批不得进入执行。
- 执行方案包含基线、目标、停止条件、回滚方式和复盘时间。
- 测试结果和可复用结论完成回写。

## 状态机验收

允许的主流程：

`待分析 -> 取证中 -> 分析中 -> 待审批 -> 已批准 -> 执行准备 -> 测试中 -> 已验证 -> 已关闭`

异常流程：

- 缺数据、无权限或工具不可用：进入 `受阻`。
- 测试失败或触发停止条件：进入 `失败待处理`。
- 二次验证推翻建议：从 `执行准备` 退回 `分析中`。

禁止行为：

- `待审批` 直接进入 `测试中`。
- 中高风险任务无审批记录进入真实执行。
- 无验收结论和知识回写直接关闭任务。

## 统一输出契约验收

每个智能体输出检查以下字段：

`结论 / 依据 / 数据来源 / 置信度 / 缺失字段 / 风险等级 / 建议动作 / 验收指标 / 人工复核`

缺少任一关键字段时，参谋长退回智能体补充，不进入审批阶段。
