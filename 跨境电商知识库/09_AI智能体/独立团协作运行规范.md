# 独立团协作运行规范

## 体系目标

Amazon-AI-OS 采用“参谋长总控 + 专项智能体 + 知识库 + MCP + 人工审批”的半自动闭环。Obsidian Vault 是唯一长期事实源；飞书是上游协作来源；卖家精灵 MCP 是外部市场数据源。

闭环状态：

`接收指令 -> 安全检查 -> 任务分析 -> 首轮取证 -> 智能体分派 -> 综合建议 -> 风险审批 -> 二次验证 -> 执行方案 -> 测试验收 -> 结果监控 -> 复盘回写`

## 总控运行流程

### 1. 接收指令与建档

参谋长先创建任务记录，至少填写：

- 任务编号、目标、站点、业务阶段和期望交付。
- 已知信息、缺失信息、限制条件和截止时间。
- 主责智能体、协作智能体、风险等级和审批人。
- 当前状态、下一动作和验收指标。

### 2. 安全检查

任何分析前必须检查：

- 是否涉及隔离资料、违规用途或平台规避。
- 是否包含未脱敏的账号、订单、客户、财务或认证信息。
- 是否涉及预算、补货、付款、账号、申诉、侵权或对外发布。
- 是否存在必须人工复核的法律、合规或经营决策。

命中禁止用途时停止正常流程，仅提供拒绝说明、风险教育或合规替代建议。

### 3. 知识与首轮取证

知识优先级：

1. 用户提供的最新店铺内部数据。
2. 卖家精灵 MCP 当前返回数据。
3. Obsidian 中已沉淀的 SOP、规则和复盘。
4. 培训资料与历史经验。

首轮取证用于建立事实基础。每次 MCP 调用必须记录工具、输入、时间、关键字段、缺失字段和数据来源。无返回或无调用次数时，标记“数据缺失”，不得补造。

### 4. 智能体分派

参谋长根据 [[智能体岗位路由表]] 分派任务：

- 每项任务指定一个主责智能体。
- 协作智能体只处理明确分项，避免重复分析。
- 所有智能体接收同一份结构化证据包。
- 专项智能体发现数据缺口时提交补充取证请求，由参谋长统一处理。

### 5. 综合建议与冲突裁决

汇总时必须区分：

- 已证实事实。
- 有依据的判断。
- 待验证假设。
- 数据缺失与人工复核项。

智能体结论冲突时，依次按数据新鲜度、内部数据优先级、证据完整度、风险保守原则裁决；无法裁决时提交人工审批。

### 6. 风险审批

| 风险等级 | 典型事项 | 默认处理 |
|---|---|---|
| 低 | 内部分析、分类、草稿、复盘 | 可自动进入执行方案 |
| 中 | Listing 修改建议、广告调整建议、运营动作 | 执行前由负责人审批 |
| 高 | 预算投入、补货付款、账号申诉、合规与侵权事项 | 负责人及专业角色审批 |

任何真实预算、付款、补货、后台发布、申诉提交和账号操作均不得自动执行。

### 7. 二次验证与执行方案

审批通过后，仅针对决策关键点进行第二轮取证：

- 验证首轮数据仍有效。
- 补齐会改变执行方案的关键字段。
- 检查最新市场、关键词、ASIN、Review 或商标数据是否冲突。

关键数据变化时，任务退回“综合建议”并重新审批。

执行方案必须包含动作、对象、负责人、优先级、时间、执行前基线、目标指标、停止条件、风险、回滚方式和复盘时间。

### 8. 测试、监控与回写

执行后按预设指标判断：

- `通过`：达到验收目标，进入复盘回写。
- `部分通过`：保留有效动作，调整未达标部分。
- `失败`：停止或回滚，记录原因并重新分析。
- `数据不足`：继续观察，不做确定结论。

任务关闭前必须完成结果记录、复盘结论和知识回写。可复用规则进入业务知识库；个案过程进入 `08_项目管理/任务主账本`。

## 任务状态机

| 状态 | 进入条件 | 允许下一状态 |
|---|---|---|
| 待分析 | 已接收指令并建档 | 取证中、受阻 |
| 取证中 | 正在读取知识或调用 MCP | 分析中、受阻 |
| 分析中 | 智能体正在输出分项结论 | 待审批、受阻 |
| 待审批 | 已形成综合建议 | 已批准、分析中、已关闭 |
| 已批准 | 审批记录完整 | 执行准备 |
| 执行准备 | 已完成二次验证与执行方案 | 测试中、分析中、受阻 |
| 测试中 | 已执行获批动作并监控 | 已验证、失败待处理、受阻 |
| 已验证 | 验收完成 | 已关闭 |
| 失败待处理 | 测试失败或触发停止条件 | 分析中、已关闭 |
| 受阻 | 缺数据、无权限或工具不可用 | 原状态、已关闭 |
| 已关闭 | 已完成回写或明确终止 | 无 |

## 统一智能体输出契约

每个专项智能体输出必须包含：

| 字段 | 要求 |
|---|---|
| 结论 | 一句话说明当前判断 |
| 依据 | 引用内部数据、知识库或 MCP 证据 |
| 数据来源 | 标明文件、报表或 MCP 工具名 |
| 置信度 | 高 / 中 / 低，并说明原因 |
| 缺失字段 | 列出会影响判断的数据 |
| 风险等级 | 低 / 中 / 高 |
| 建议动作 | 明确对象、负责人和优先级 |
| 验收指标 | 可观测、可复盘 |
| 人工复核 | 标明审批人或专业角色 |

## 能力降级

- 卖家精灵 MCP 无次数或无返回：只做框架分析，明确缺失字段。
- 飞书未授权：仅使用已同步到 Obsidian 的资料。
- 内部数据缺失：不得计算利润、明确补货量或大幅调整预算。
- 二次验证不可用：中高风险任务保持“受阻”，不得进入真实执行。

## 双层调度与调用留痕

- Codex 原生调度层用于正式任务中的真实专项智能体调用。每次调用必须记录任务编号、已注册智能体 ID、职责、调用 ID、状态和结果契约检查。
- 独立调度层使用 `work/amazon-ai-os/queue` 本地任务队列；Obsidian 任务主账本仍是审批状态和最终结果的唯一事实源。
- 同一任务、智能体和职责组成幂等键，不得重复分派。输出缺少统一契约字段时，退回原智能体补充，不得创建替代智能体。
- 独立调度层真实模型适配器缺少凭证或网络能力时进入“受阻”；测试适配器只用于验证路由、状态机和门禁，不得冒充真实专项结论。
- 中高风险任务即使审批通过，缺少二次验证、测试结果、监控计划或知识回写时，也只能停留在“执行准备”，不得标记为“已验证”或“已关闭”。
